# Agent Boundaries Rule

Use this rule for agent-driven tasks.

## Required Flow

1. Read `AGENTS.md`.
2. Read the relevant docs under `docs/`.
3. Inspect the current `main` branch.
4. Keep the change within the Issue or Spec Context.
5. Report verification commands.

## Boundaries

- Do not expand scope without updating the Spec Context.
- Do not weaken tests to make a PR pass.
- Do not change defaults without compatibility notes.
- Do not create broad rewrites when a targeted fix is enough.

## PR Review

Use `docs/specs/pr-review-checklist.md` for review comments and merge readiness.
